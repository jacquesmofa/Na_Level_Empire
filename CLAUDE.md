# CLAUDE.md — Na Level Empire Media website

Read this before changing anything. It describes the target state of the
project; sections marked **(target)** are being built in phases a–f and may
not exist yet. Where the code and this file disagree, ask before "fixing"
either one.

## What this is

Marketing site for Na Level Empire Media (NLEM), a Toronto audiovisual
production and event management social enterprise. Eight pages: Home,
Projects, Media Hub, News, Social Impact, Careers, About, Contact (+ 404).

Originally generated by Readdy.ai. Being refactored so non-technical editors
change all copy and images through a CMS, at zero ongoing cost.

## Content rules (non-negotiable)

1. **No hardcoded copy or image URLs in components.** Every visible string,
   list item, link and image comes from `src/content/` via
   `src/content/index.ts`. Components receive typed data; they never import
   JSON directly. Allowed in code: CSS classes, ARIA attributes that are not
   visible copy, route paths in the router config.
2. **Zod is the contract.** Every JSON file has a schema in
   `src/content/schema.ts`; TypeScript types are `z.infer<>` of those schemas,
   never written by hand. When you add a field: schema first, then JSON, then
   `public/admin/config.yml`, then the component.
3. **A bad edit fails the build, never the live site.** `npm run validate`
   runs before every build (locally and in CI). Error messages must name the
   file and the field in plain English, because editors read them.
4. **The CMS config mirrors the schema.** Field names in `config.yml` must
   exist in the Zod schema (checked by a script). Every CMS field gets a
   friendly `label` and, where useful, a `hint`. Lengths and required flags
   match the schema.
5. **Content edits, not layout edits.** Editors change content inside a fixed
   design. Adding a new section type is a developer change.
6. **Keep the visual design identical** unless the owner has approved a
   change. Refactors are verified with before/after screenshots.

## Image convention

- Content stores the **plain Cloudinary delivery URL** as uploaded, e.g.
  `https://res.cloudinary.com/<cloud>/image/upload/v1712345678/nlem/projects/gala.jpg`.
  No transformations stored in content. Every image also stores `alt`.
- Components render images only through `<CmsImage>`, which calls
  `src/lib/image.ts`:
  - `cld(url, { width })` inserts `f_auto,q_auto,w_<width>,c_limit` right
    after `/upload/`.
  - `cldSrcSet(url, [400, 800, 1200, 1600])` builds the `srcset`.
- `<CmsImage>` always sets `width`, `height` (from the layout's aspect ratio),
  `sizes`, `decoding="async"`, and `loading="lazy"` except for the first
  visible image on a page (`loading="eager"`, `fetchPriority="high"`).
- Zod rejects image URLs that are not on our Cloudinary cloud.
- YouTube thumbnails come from the video URL, not Cloudinary.

## Styling

- Brand tokens: charcoal `#2C2C2E`, deep `#1E1E20`, gold `#C8922A`,
  cream `#FDFCF0`. Fonts: Bebas Neue (headlines), Syne (labels, buttons),
  DM Sans (body). Use the Tailwind token names, not hex values.
- Opacity modifiers must be on Tailwind's scale (`/10`, `/15`, `/20` …) or
  bracketed (`/[0.97]`). Values like `/97`, `/8`, `/12` are silently dropped
  in Tailwind 3.
- Icons: the named icon set in `ui/Icon`; editors pick from a dropdown.

## Deploy flow (target)

1. A developer push or a CMS save lands on `main`.
2. `deploy.yml` runs: `npm ci` → lint → typecheck → validate → build →
   prerender → sitemap.
3. If any step fails, nothing is uploaded and the live site is untouched.
4. `dist/` is uploaded by SFTP (or FTPS if the host has no SSH); only changed
   files are sent; one deploy runs at a time.
5. Live in about 2–3 minutes. Pull requests run the same checks without
   deploying.

Credentials live only in GitHub Secrets: `DEPLOY_HOST`, `DEPLOY_USER`,
`DEPLOY_PASSWORD` or `DEPLOY_SSH_KEY`, `DEPLOY_DIR`. The CMS OAuth secret
lives in the OAuth relay (Cloudflare Worker), never in this repo. Cloudinary
cloud name and public API key may appear in `config.yml`; the API secret
never appears anywhere in the repo.

- Run `npm run check` and `npm run build` before declaring a step done.
- Ask before any visible design change, deleting content, or touching
