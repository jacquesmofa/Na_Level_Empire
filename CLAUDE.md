# CLAUDE.md — Na Level Empire Media website

Read this before changing anything. It describes the agreed target state;
items marked **(target)** are being built in phases a–f and may not exist
yet. Where the code and this file disagree, ask before "fixing" either one.
Decisions recorded here were made by the owner on 17 Oct 2026.

## What this is

Bilingual (English + French) marketing site for Na Level Empire Media
(NLEM), a Toronto audiovisual production and event management social
enterprise. Originally generated by Readdy.ai; being refactored so editors
change everything — text, images, lists, and whole page sections — through
a CMS, at zero ongoing cost.

## Content model

- **Settings** (`settings/{locale}/site.json`): site name, logo, contact
  details, social links, navigation, footer, SEO defaults.
- **Pages** (`pages/{locale}/<page>.json`): `seo` + `sections[]`, an ordered
  list of typed blocks. Editors add, remove and reorder blocks. Each block
  type is pre-designed in the brand system, so any combination stays on
  brand. Block types (target): `hero`, `pageHeader`, `textImage`,
  `richText`, `quote`, `cardGrid`, `statsBand`, `metricTiles`, `gallery`,
  `video`, `partners`, `callToAction`, `form` (quote | newsletter), plus
  blocks that list a collection: `projectsGrid`, `latestWork`, `newsFeed`,
  `jobsList`, `videoGrid`, `teamGrid`.
- Blocks are a **Zod discriminated union on `type`**, mirrored in the CMS as
  a list field with variable `types` (`typeKey: type`).
- **Collections**: projects, news, jobs, videos, team — one file per item.
  News items have `slug` and an optional Markdown `body` so `/news/<slug>`
  pages can be added later without restructuring. Videos store a YouTube
  URL entered by hand (no API key); no view counts. A `source` field leaves
  room for automatic fetching later.
- **Bilingual**: Sveltia i18n with `structure: multiple_folders`, locales
  `en` (default) and `fr`. Translatable text uses `i18n: true`; images,
  links, numbers and order use `i18n: duplicate`. French URLs are `/fr/...`.
- **Numbers that are goals**: stats have a `kind` of `result` or `target`;
  targets render with visible "Target" / "Objectif" wording until confirmed.
- **Placeholders**: unconfirmed content carries `"placeholder": true` where
  the schema allows it, and every placeholder is listed in `PLACEHOLDERS.md`.

## Content rules (non-negotiable)

1. **No hardcoded copy or image URLs in components.** Every visible string,
   link and image comes from `src/content/` through `src/content/index.ts`.
   Allowed in code: CSS classes, non-visible ARIA, route patterns.
2. **Zod is the contract.** Types are `z.infer<>` of the schemas, never
   hand-written. To add a field or block: schema → JSON → `config.yml` →
   component.
3. **A bad edit fails the build, never the live site.** `npm run validate`
   runs before `vite build`. If it fails, Vercel keeps serving the previous
   deployment. Errors name the file and field in plain English.
4. **CMS config mirrors the schema.** `scripts/check-cms-config.ts` fails CI
   if `public/admin/config.yml` and the Zod schema disagree.
5. **Design stays identical** unless the owner approves a change; visual
   changes ship with before/after screenshots in the PR.

## Images (target)

- Content stores the plain Cloudinary URL as uploaded, e.g.
  `https://res.cloudinary.com/beavj5sp/image/upload/v1712345678/nlem/projects/gala.jpg`,
  plus `alt` text. No transformations stored in content.
- Render images only through `<CmsImage>` → `src/lib/image.ts`:
  `cld(url, { width })` inserts `f_auto,q_auto,w_<width>,c_limit` after
  `/upload/`; `cldSrcSet(url, widths)` builds `srcset`. Always set `width`,
  `height`, `sizes`, `decoding="async"`, `loading="lazy"` (first visible
  image: `eager` + `fetchPriority="high"`).
- Zod rejects any image not under `res.cloudinary.com/beavj5sp/.../nlem/`.
  No `readdy.ai` or `readdy-site.link` URL may remain after phase (c).
- `config.yml` may contain only the cloud name `beavj5sp` and the public
  API key. **The Cloudinary API secret never appears in the repo, config
  files, environment variables of this project, or chat.** Editors upload
  through Cloudinary's Media Library widget with their own Cloudinary login.
- YouTube thumbnails come from the video URL.

## Styling

- Tokens: charcoal `#2C2C2E`, deep `#1E1E20`, gold `#C8922A`, cream
  `#FDFCF0`; Bebas Neue (headlines), Syne (labels/buttons), DM Sans (body).
  Use token names, not hex values (target).
- Tailwind 3 opacity steps are multiples of 5 or bracketed (`/[0.97]`);
  `/97`, `/8`, `/12` are silently dropped.
- Icons come from the named set in `ui/Icon`; editors pick from a dropdown.

## Deploy and environment

1. Work happens on one branch + pull request per phase. Never commit to
   `main` directly; the owner reviews the Vercel preview and merges.
2. Vercel builds every pull request (preview URL) and every change on
   `main` (production). CI runs the same checks on pull requests.
3. CMS saves commit straight to `main` and go live in a few minutes. This
   is intended (no draft workflow). Note: `/admin` on a preview still edits
   `main`, i.e. the live site.

Vercel environment variables (Project → Settings → Environment Variables);
nothing secret is ever committed:

| Name | Secret? | Used by |
| --- | --- | --- |
| `VITE_WEB3FORMS_ACCESS_KEY` | no (public by design) | forms, baked in at build |
| `GITHUB_OAUTH_ID` | no | `api/auth.ts` (target) |
| `GITHUB_OAUTH_SECRET` | **yes** | `api/callback.ts` (target) |
| `CMS_ALLOWED_ORIGINS` | no | relay: which sites may receive a login token (target) |
